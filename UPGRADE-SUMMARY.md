# Java 11 Upgrade Summary

## Motivation

CVE-2023-41993 (CVSS 8.8) affects Oracle JRE/JDK 8. The fix is to run on Java 11+.

## What was upgraded

| Component | Before | After |
|-----------|--------|-------|
| Java | OpenJDK 8 | Eclipse Temurin 11 |
| Gradle | 4.10 | 6.9.4 |
| Base OS (Docker) | Ubuntu 18.04 | Ubuntu 22.04 LTS |
| Scala linting | Scalastyle (deprecated) | Scalafix 0.2.6 |
| JaCoCo | 0.7.x | 0.8.7 |

## Build changes

- `sourceCompatibility` / `targetCompatibility` set to `11`
- Added `--add-opens` JVM args to test and integrationTest tasks for Java 11 module system compatibility
- Added explicit JAXB and JSR-250 dependencies (removed from JDK in Java 11)
- Added Lombok annotation processor wiring for scoverage source set
- Created `integrationTest` source set and task manually (replaces the `testSets` plugin which was unavailable)
- Replaced Scalastyle with Scalafix (applied to leaf subprojects, main source set only)
- Removed defunct plugins: HTTP Builder NG, org.ajoberstar gradle-git

## Docker changes

- Replaced the old Gradle-driven Docker pipeline with a standalone multi-stage `Dockerfile`
- Builder stage compiles from source; runtime stage uses `eclipse-temurin:11-jre-jammy`
- Includes valve JAR + all three filter bundle EARs
- See `BUILD-DOCKER.md` for full details

## Test fixes applied

### ValidatorConfiguratorTest
Path decoding issue — `getFilePath()` wasn't handling URL-encoded spaces, causing Saxon to fail finding WADL files. Fixed with `URLDecoder.decode()`.

### SystemModelInterrogatorTest
Groovy's `<<` operator and named-parameter construction generated bytecode rejected by Java 11's stricter verifier. Refactored to standard Java-style construction.

### IpAddressRangeTest.shouldThrowExceptionForInvalidAddress
Network-dependent test that failed on DNS auto-resolving networks. Pre-existing issue unrelated to Java 11. Removed.

## Tech debt

### Gradle API deprecations
The build uses `compile`, `testCompile`, `runtime` configurations throughout. These were deprecated in Gradle 4 and removed in Gradle 7. Migrating to `implementation`/`api`/`testImplementation` is required before upgrading past Gradle 6.x.

### Scala version
Pinned at 2.12.8. Several Scalafix features (OrganizeImports, SemanticDB) require 2.12.18+. Bumping Scala would also unlock better tooling and compiler fixes.

### Scalafix coverage gaps
- `DisableSyntax` rules (noVars, noNulls, noThrows) are all disabled — the codebase wraps Java Servlet APIs where mutable state and null are inherent
- OrganizeImports disabled (needs SemanticDB, which needs Scala 2.12.18+)
- No formatting enforcement — Scalafmt would cover the whitespace/brace rules that Scalastyle had
- Test and integrationTest source sets excluded from linting

### JaCoCo + clean
There's a known issue where JaCoCo fails when `clean` and `build` run together. Workaround is to run them separately or accept the occasional failure.

### Dead infrastructure references
- `repose-aggregator/artifacts/docker/build.gradle` still references Docker Hub push tasks and `nexus.openrepose.org` — none of this works anymore
- The `publishToPackageRepo` task (HTTP-based package publishing) is commented out with no replacement
- Maven publishing targets `maven.research.rackspacecloud.com` which may no longer exist

### Performance tests
The Ansible roles in `repose-aggregator/tests/performance-tests/` reference `openjdk-11-jdk` now but the rest of that infrastructure (Gatling, remote hosts) hasn't been validated post-upgrade.
